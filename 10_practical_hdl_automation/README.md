# Phase 10: Practical HDL Automation with Tcl

## 1. Objective

This phase applies Tcl scripting to practical Verilog HDL projects. The goal is to automate the complete simulation workflow using **Tcl, Icarus Verilog, VVP, and GTKWave**.

The phase contains three projects:

1. D Flip-Flop
2. 4-Bit ALU
3. UART Transmitter and Receiver

For each project, Tcl helps coordinate compilation, simulation, output capture, log generation, and report creation. VCD waveform files can be opened in GTKWave for signal-level inspection.

## 2. Tools Used

| Tool | Purpose |
|---|---|
| Tcl | Automates the workflow and handles command execution |
| Icarus Verilog (`iverilog`) | Compiles Verilog design and testbench files |
| VVP (`vvp`) | Executes the compiled simulation |
| GTKWave (`gtkwave`) | Displays VCD waveform files |
| Ubuntu/WSL | Environment used for the HDL automation workflow |

## 3. Overall Automation Flow

```text
Verilog Design + Testbench
           |
           v
       run.tcl
           |
           v
 Compile using iverilog
           |
           v
   Simulation executable
           |
           v
     Execute using vvp
           |
           v
 Capture output and logs
           |
           v
 Generate project reports
           |
           v
 Create VCD waveform
           |
           v
 Inspect waveform in GTKWave
```

The testbench generates the VCD file through `$dumpfile` and `$dumpvars`. Tcl coordinates the external commands and output files.

## 4. Project 1: D Flip-Flop

**Directory:** `01_d_flip_flop/`

### Files

| File | Purpose |
|---|---|
| `D_flip_flop_behav.v` | Behavioral D flip-flop design |
| `D_flip_flop_tb.v` | Testbench |
| `run.tcl` | Tcl automation script |
| `dff_sim` | Compiled simulation executable |
| `simulation.log` | Simulation log |
| `dff.vcd` | Waveform data |
| `waveform.png` | Saved waveform image |

### Step 1: Compile the design

Run these commands from the D flip-flop project directory in Ubuntu/WSL:

```bash
iverilog -o dff_sim D_flip_flop_behav.v D_flip_flop_tb.v
```

The `-o dff_sim` option specifies the name of the compiled simulation executable.

### Step 2: Run the simulation

```bash
vvp dff_sim
```

The testbench drives the D input and clock, allowing the flip-flop's output behavior to be observed.

### Step 3: Inspect the waveform

```bash
gtkwave dff.vcd
```

The waveform file is generated by the testbench. GTKWave displays signals such as the clock, input D, and output Q, depending on the signals declared and dumped in the testbench.

### Step 4: Automate the workflow

The `run.tcl` script coordinates compilation and simulation. Tcl's `exec` runs external commands, while `catch` detects command failures.

The expected workflow is:

1. Compile the Verilog files.
2. Execute the simulation.
3. Capture simulation output in `simulation.log`.
4. Retain `dff.vcd` for waveform inspection.
5. Open GTKWave when visual inspection is required.

## 7. Tcl Automation: `run.tcl`

Each project has its own `run.tcl` file. The purpose is to automate the same general sequence instead of repeatedly entering compilation and simulation commands manually.

### Important Tcl commands

| Tcl command | Purpose |
|---|---|
| `exec` | Runs external programs such as `iverilog` and `vvp` |
| `catch` | Detects errors raised while executing a Tcl script or command |
| `puts` | Prints messages or writes text to an open file channel |
| `open` | Opens a file for reading or writing |
| `close` | Closes an open file channel |

### Example of the automation pattern

The following is a compact illustrative pattern showing how Tcl can run the D flip-flop commands and save the simulation output. It explains the approach; it is not a verbatim copy of the existing project `run.tcl` file.

```tcl
set compile_cmd {iverilog -o dff_sim D_flip_flop_behav.v D_flip_flop_tb.v}

if {[catch {exec {*}$compile_cmd} compile_output]} {
    puts "Compilation failed: $compile_output"
    exit 1
}

if {[catch {exec vvp dff_sim} sim_output]} {
    puts "Simulation failed: $sim_output"
    exit 1
}

set log_file [open "simulation.log" w]
puts $log_file $sim_output
close $log_file

puts "Simulation completed."
```

This pattern demonstrates:

1. `exec` invokes the compiler and simulator.
2. `catch` checks whether either command failed.
3. `exit 1` indicates a failure to the calling environment.
4. `open`, `puts`, and `close` write captured output to a log file.

**Note:** The exact commands, redirection behavior, report contents, and error-handling logic depend on the actual `run.tcl` script in each project. If a project uses shell redirection or a different logging method, preserve that project's implementation.

## 8. Running the Projects

Open Ubuntu/WSL and change to the appropriate project directory before executing the commands. For example:

```bash
cd /path/to/10_practical_hdl_automation/01_d_flip_flop
tclsh run.tcl
```

For the other projects, enter their directories before running the respective Tcl script:

```bash
cd /path/to/10_practical_hdl_automation/02_alu_4_bit
tclsh run.tcl
```

```bash
cd /path/to/10_practical_hdl_automation/03_uart
tclsh run.tcl
```

Replace `/path/to/` with the actual location of the repository in your Ubuntu/WSL environment.

Running from the correct directory matters because relative file paths used by `run.tcl`, the compiler, and the testbench are generally resolved against the current working directory.

If `tclsh` or `iverilog` is not found, check that the corresponding tool is installed and available on the environment's `PATH`.

## 9. Troubleshooting

| Problem | What to check |
|---|---|
| `iverilog` command not found | Confirm Icarus Verilog is installed in the active Ubuntu/WSL environment |
| Source file not found | Check the current directory and exact file names |
| Simulation executable not found | Check the compiler output and whether compilation succeeded |
| Simulation output missing | Review the simulator exit status and `simulation.log` |
| VCD file missing | Check that the testbench calls `$dumpfile` and `$dumpvars` and that the simulation reaches those statements |
| GTKWave cannot open the VCD | Verify that the VCD file exists and contains waveform data |
| Report is empty or incomplete | Review the report-generation logic and the captured simulation output |

After completing Phase 10, the key skills practiced are:

- Using Tcl to coordinate external HDL tools.
- Compiling Verilog designs and testbenches with Icarus Verilog.
- Running simulations with VVP.
- Capturing simulation output and maintaining logs.
- Generating and inspecting VCD waveform files.

## Conclusion

Phase 10 connects the Tcl concepts learned in earlier phases to practical HDL projects. The D flip-flop establishes the basic flow, the 4-bit ALU applies it to a combinational design, and the UART extends it to a multi-module communication design.

The central lesson is that Tcl can make compilation, simulation, logging, and result organization repeatable, reducing manual work when testing HDL designs.
